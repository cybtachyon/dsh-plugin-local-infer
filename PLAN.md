# PLAN: Refactor `dsh/client.js` to modular TypeScript (Option B)

## Goal

Replace the 4,628-line hand-written lazy-CJS browser card with a modular
TypeScript source tree that builds (via esbuild) to the same single
`dsh/client.js` lazy-CJS artifact. The refactor must also fix the two
structural defects that cause UI desyncs:

1. **Multiple sources of truth.** "Is the engine running" is tracked in four
   places today (`draftRunningState`, the `entryLaunch` machine,
   `providerStatusRef`, `data.providers[].status`). The title-bar
   Launch/Stop control is a 4-way conditional over all of them.
2. **Server-coupled rendering.** Components read server summary values to
   decide what to render, instead of updating a client-side draft first and
   syncing to the server.

After this plan: one store holds all card state, actions are the only
mutators, every server round trip is a `pending -> ack | timeout`
transition (TCP-style), and components render only from the store.

## Hard constraints

- **Artifact contract.** `dsh/client.js` stays a single file that calls
  `window.__ModuleLoader__.load({ id: 'dsh-plugin-local-infer', factory:
  (require) => { ... } })`. The factory body must return `module.exports`
  with `apply` and `inject`.
- **Runtime externals.** `react` and
  `@deepseek-ai/dsh-client-ui-primitives` resolve at runtime through the
  injected `require` (the shell's frozen platform module table). They must
  not be bundled. The bundle must emit exactly those two runtime requires.
- **JSX transform.** Use the classic transform with
  `jsxFactory: 'react.createElement'` and
  `jsxFragmentFactory: 'react.Fragment'`. Do not use the automatic
  runtime: `react/jsx-runtime` is not in the platform module table.
- **Build step is acceptable.** `pnpm build` may produce `dsh/client.js`.
  The client TypeScript source is not shipped: the root `package.json`
  `files` list ships only `dsh/client.js` and `dsh/host.js` from the
  client half.
- **Tooling.** Join the existing gates: `tsc -b` (project reference),
  vitest (`packages/*/tests/**/*.spec.ts`, coverage thresholds defined
  in `vitest.config.ts`), eslint (`eslint .`).

### Build pipeline

`scripts/build-client.mjs` runs after `tsc -b`:

1. esbuild: `bundle: true`, `format: 'cjs'`, `platform: 'browser'`,
   `target: 'es2020'`, `external: ['react',
   '@deepseek-ai/dsh-client-ui-primitives']`, entry
   `packages/client/src/index.ts`, outfile `dsh/.build/client.cjs`.
2. Wrap the CJS output:

   ```js
   // generated by scripts/build-client.mjs. Do not edit.
   window.__ModuleLoader__.load({
     id: 'dsh-plugin-local-infer',
     factory: (require) => {
       var module = { exports: {} };
       var exports = module.exports;
       /* <contents of dsh/.build/client.cjs> */
       return module.exports;
     },
   });
   ```

   esbuild's CJS external shim resolves `require` dynamically
   (`typeof require !== 'undefined' ? require : ...`), so inside the factory
   it picks up the injected platform-table `require`. No other changes to
   the loader contract.
3. Write `dsh/client.js`.

Root `package.json` script becomes `"build": "tsc -b && node
scripts/build-client.mjs"`.

### Store invariants (the desync fix)

- `CardState.draft` is the only source for form field values. `summary`
  (the last server ack) is never rendered as a form value. On
  `summary/ack`, persisted fields merge into the draft field-level
  (platform entries merge per-engine, preserving local edits), the same
  merge the current `fetchSummary` does by hand.
- `CardState.launch` (the per-provider machine, driven only by
  `launch/move` through `launchNextState`) is the only source for
  lifecycle state. The local state variables that duplicate it are
  deleted (this is the canonical "deleted state" list the tasks and the
  plan DoD grep reference): `draftRunningState`, `entryLaunchState`,
  `providerStatusRef`, `mirroredStatus`, `mirroredPhaseLabel`. The
  title-bar control renders from one derivation:
  `deriveLifecycleControl(state)`.
- Every server mutation goes through `performAction(key, run, timeoutMs)`:
  dispatch `action/start`, run `run()`, dispatch `action/ack` or
  `action/fail`; a deadline timer dispatches `action/timeout`
  (`pending -> error`). A late ack after the timeout is a no-op (the
  reducer ignores `action/ack` when the action is no longer `pending`).
  Timeouts: launch 150 s (the route's health-poll cap), stop 10 s,
  get/download/install 120 s, others 30 s.
- Field edits are local-only: update `draft`, set `dirty`, clear the
  touched notes, and schedule the 300 ms debounced re-price (a read, not a
  mutation: it refreshes `summary` + `deps`).
- UI-local state (help, autoRebuild, agentDefault, provider form mode,
  log path, logs pane) lives under `CardState.ui` and is never synced.

### Type reuse

Import view-model types from the ui package with `import type` only
(erased at bundle time, so no runtime dependency):
`LocalInferSummary`, `ProviderSummaryEntry`, `DepsModel`, `MeterModel`,
`WarningsModel` from `dsh-plugin-local-infer/ui`. The client tsconfig
references `../ui`; the tsconfig.base.json facade gains the
`dsh-plugin-local-infer/client` path alias.

### GUI walkthrough checklist

Applies to T3.8, T3.9, and T4.2. Load the
card (summary fetch, meter, provider list); edit a field (dirty gate,
debounced re-price); Save (ack, dirty clears); Discard; Launch a
provider entry (phase labels, running -> Stop, stop fast-poll,
failed -> red Logs); Stop; Get (streamed logs, idle re-enable);
Download model; chat-template auto-download; Register/Remove; help
toggle persistence; logs scroll/resize; title-bar and entry controls
agree at every step of a launch/stop cycle while a provider is
edited.

## Plan definition of done

- `pnpm build && pnpm test:coverage && pnpm lint` all green.
- `dsh/client.js` is generated, passes `node --check`, contains exactly
  two runtime `require` calls, and the GUI walkthrough checklist passes.
- `grep -rn "draftRunningState\|entryLaunchState\|providerStatusRef\|mirroredStatus\|mirroredPhaseLabel"
  packages/client/src` returns nothing (the Store invariants "deleted
  state" list): lifecycle state has one source (`state.launch`) and one
  derivation (`deriveLifecycleControl`).
- Every server mutation in the card goes through `performAction`
  (verifiable by grep: no raw `fetch(` outside `src/api/routes.ts`).

## Rollback

The old hand-written `dsh/client.js` stays in git until T3.9. Rollback at
any point: `git checkout -- dsh/client.js` and revert the root `build`
script to `tsc -b`. The artifact is regenerable at any time with
`pnpm build`.
